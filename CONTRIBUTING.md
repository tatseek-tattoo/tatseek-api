# Feedback and contributions

We welcome bug reports, reasoned criticism, integration ideas and documentation
improvements. You do not need to submit code to contribute.

## Report an API or example problem

Open an issue with: endpoint and query parameters; time of the request; HTTP
status; the relevant response field; expected versus observed behavior; and a
TatSeek page link if it helps reproduce the issue. Keep reports small. Do not
post credentials, private contact details, photographs, or bulk catalogue dumps.
An issue is a feedback channel, not a promised support SLA.

## Suggest a vocabulary or interpretation change

Explain the concept, give examples via source links, identify the axis, and say
why an existing term is insufficient. Distinguish a new concept, synonym,
translation, wrong tag and missing annotation. Suggested changes do not become
live API codes until accepted in the provider's published vocabulary.

## Improve these files

Keep examples dependency-light, read-only, small and respectful of attribution.
Verify code against the live API with modest requests. Record the date and avoid
fixed result counts or permanent-ID assumptions. Do not change the schema or
vocabulary snapshot independently of its source without clearly labelling a
derived proposal. Note changes in CHANGELOG.md.

For copyright, removal or personal-data concerns, use the contact/removal channel
on [TatSeek](https://tatseek.com/) rather than publishing the underlying material
in a public issue.
